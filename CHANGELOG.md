## [Unreleased]

### Changed
- `grafana/dashboards/weather.json`: "Current Conditions by Station" now also selects `EXTRACT(EPOCH FROM (now() - ts)) AS age` and renders it as a color-coded duration column (teal = fresh, `#dbf4a7` > 30 min, `#a24936` > 5 h), so a single dead station (e.g. `W05_VALENCIA_UPV_10m`, frozen upstream since 2026-02-05) is visible at a glance instead of being discovered via ad-hoc SQL.
- `grafana/provisioning/datasources/alertmanager.yml`: added `handleGrafanaManagedAlerts: true` so Grafana-managed alerts are forwarded to the existing Alertmanager and reuse its email routing/inhibition rules.
- `grafana/README.md`, `monitoring/README.md`: documented the new `age` column, the `WeatherStationStale` rule, and the Grafana→Alertmanager forwarding (alert provisioning files are loaded at Grafana startup only, so YAML changes need a container restart).
- Live Grafana instance: restarted the container to load the alert provisioning, and set the ngalert admin configuration to `{"alertmanagersChoice": "external"}` via `POST /api/v1/ngalert/admin_config`. This DB-stored, non-provisionable setting is required for the datasource-level `handleGrafanaManagedAlerts` toggle to take effect (without an admin-config row the sender never discovers external Alertmanagers and keeps notifying only the SMTP-less internal notifier); the one-time step is documented in `grafana/README.md`. Verified end-to-end: `WeatherStationStale{fiwareid=W05_VALENCIA_UPV_10m}` delivered to Alertmanager with the rendered stale-hours annotation.
- **Upstream data source migrated from `valencia.opendatasoft.com` to the city geoportal’s ArcGIS REST endpoint.** The Opendatasoft host stopped serving the project’s datasets some time before 2026-05-09: TLS 1.3 ClientHello returns `internal_error` on every IP, TLS 1.2 lands on an unrelated tenant returning HTTP 404. New base URL: `https://geoportal.valencia.es/server/rest/services/OPENDATA/MedioAmbiente/MapServer`, layer `156` for air pollution, layer `157` for weather. Field names (`fiwareid`, `fecha_carg`, `so2/no2/o3/co/pm10/pm25`, `calidad_am`, `viento_dir/_vel`, `temperatur`, `humedad_re`, `presion_ba`, `precipitac`) and station identifiers map 1:1, so the Avro schemas (`schemas/*.avsc`), Kafka topics (`vlc.air`, `vlc.weather`), JDBC sink configs (`connect/config/jdbc-sink.timescale.*.json`), TimescaleDB tables (`air.hyper`, `weather.hyper`), dbt models, and Grafana dashboards are unchanged.
- `producer/air_producer.py`, `producer/weather_producer.py`: rewritten against the ArcGIS `/query` endpoint. New shared module `producer/arcgis_client.py` encapsulates HTTP + paging (`resultRecordCount`/`resultOffset`, `outFields`, `orderByFields=fecha_carg DESC`, `outSR=4326`). `fecha_carg` is forwarded directly as epoch-ms `timestamp-millis` (was: ISO string → epoch ms). `extract_lat_lon` now reads `feature.geometry = {x: lon, y: lat}` and keeps a fallback for the legacy `geo_point_2d` shape used in tests. The dual-base Opendatasoft fallback (`VLC_EXPLORE_BASE` + `VLC_EXPLORE_BASE2`) is gone.
- `.env.example`: replaced `VLC_EXPLORE_BASE`, `VLC_EXPLORE_BASE2`, `VLC_DATASET_ID_1`, `VLC_DATASET_ID_2` with a single `VLC_ARCGIS_BASE`. Bumped `PAGE_LIMIT` default from 100 to 2000 (ArcGIS layer `maxRecordCount`). Added `VLC_STALE_WARN_EVERY` so empty-poll warnings can be tuned.
- `compose/docker-compose.yml`: replaced `VLC_DATASET_ID` env on `air-producer` / `weather-producer` with `VLC_LAYER_ID: "156"` / `"157"`.
- `producer/README.md`: rewritten to describe the ArcGIS source, the new query parameters, the field renames at the producer boundary, and the new env vars.
- `README.md`: data-flow diagram updated to reflect the ArcGIS source and added a one-paragraph migration note.
- `docs/architecture.mmd`: source subgraph relabelled "Source APIs (geoportal.valencia.es ArcGIS REST)"; ingestion node now describes `outFields` / `resultOffset` / `outSR=4326` / per-station offsets; the backfill subgraph now points at the local CSVs in `backfill/` instead of the dead Opendatasoft export endpoint.
- `docs/README.md`, `docs/station_mapping.md`, `docs/abbrev_term.txt`: link/description updates referencing the geoportal layers; added an `ArcGIS` glossary entry; left the existing `ODS` entry as historical context.
- `scripts/check_frequency.py`, `scripts/weather_frequency_check.py`, `scripts/weather_snapshot_watcher.py`, `scripts/print/print_air_geo.py`, `scripts/print/print_air_measurements.py`, `scripts/analyze/analyze_stations.py`, `scripts/analyze/analyze_measurements.py`, `scripts/analyze/analyze_weather_measurements.py`, `scripts/vlc_air_fields_dtype.ps1`, `scripts/vlc_weather_fields_dtype.ps1`: rewritten to hit the ArcGIS `/query` endpoint, parse `features[*].attributes` + `features[*].geometry`, and treat `fecha_carg` as epoch ms. Output formats unchanged.
- `db/direct_sql_queries.txt`: the `SELECT … FROM weather.daily;` "daily trends" query now also projects `precip_total_mm`.
- Live TimescaleDB instance: applied the schema change to add `precip_total_mm` to `weather.daily` and `weather.weekly`. Because TimescaleDB continuous aggregates cannot be `ALTER`ed to add columns and cannot be (re)created inside an explicit transaction, the migration ran outside a transaction: dropped the dependent regular view `weather.daily_trends`, dropped both continuous aggregates, recreated them with the new column, reattached their existing refresh policies, and recreated `weather.daily_trends` (now also exposing `precip_total_mm`) with `SELECT` granted to `vlc_dev`.

### Added
- `grafana/provisioning/alerting/vlc-staleness.yml`: Grafana-managed alert rule `WeatherStationStale` (folder `VLC`, evaluated every 5 m, `for: 5m`, severity `warning`): queries TimescaleDB for `EXTRACT(EPOCH FROM (now() - max(ts))) / 3600.0` per `fiwareid` in `weather.hyper` and fires one alert instance per station exceeding 5 hours of staleness. Complements the topic-level Prometheus `NoWeatherDataIngested` alert, which cannot detect a single dead station while the rest of the fleet keeps publishing. Verified live: `W05_VALENCIA_UPV_10m` (≈3555 h stale) enters `Pending`→`Firing`, all other stations stay `Normal`.
- `producer/arcgis_client.py`: shared ArcGIS REST client (`get_layer_metadata`, `get_field_names`, `fetch_one_feature`, `fetch_page`).
- Stale-upstream heartbeat in both producers: after `VLC_STALE_WARN_EVERY` consecutive empty cycles (default 12 ≈ 1 hour at the 5-minute cadence) the log line includes how long it has been since the last successful emit.
- `db/init/010-bootstrap.sql`: `weather.daily` and `weather.weekly` continuous aggregates now expose `sum(precip_mm) AS precip_total_mm` alongside the existing `max(precip_mm) AS precip_max_mm`. The `max` is the peak per-interval rainfall intensity in the bucket; `sum` is the bucket's total rainfall (since each `precip_mm` row is the rainfall accumulated within that station's reporting interval).
- `grafana/dashboards/weather.json`: new "Daily Precipitation Total - All Stations (Last 30 days)" panel sourcing `weather.daily.precip_total_mm` (full-width bar chart, `lengthmm` unit, legend `sum` reducer). The existing 7-day per-reading precipitation panel is kept for intensity views.
- `db/direct_sql_queries.txt`: "Records of records" block that surfaces the row holding each meteorological extreme (`max/min` of `temperature_c`, `humidity_pct`, `pressure_hpa`, `wind_speed_ms`; `max` of `precip_mm`) via per-metric `UNION ALL` subqueries.
- `db/direct_sql_queries.txt`: all weather hourly-aggregate variants (since-always, since-Monday, since-today, hour-of-day across all years) now also select `SUM(precip_mm) AS precip_total_mm` next to `MAX(precip_mm) AS precip_max_mm`.
- `scripts/arcgis_bulk_download.py`: ArcGIS-side bulk catalog dumper, the replacement for the legacy Opendatasoft `scripts/bulk_download.py`. Pure stdlib (`urllib.request`), no new dependencies. Recursively walks `<base>/services?f=json` to discover every folder/service, enumerates `layers[]` + `tables[]` on each MapServer/FeatureServer, and writes a per-layer folder named `<folder>__<service>__<layer_id>__<slug>/` with `<slug>_full_<ts>.json` (features array; Point geometry flattened to `lon`/`lat`, other geometry kept under `_geometry`) and `<slug>_metadata_<ts>.json` (download manifest + ArcGIS layer JSON). Pagination honors the layer's `maxRecordCount` and `exceededTransferLimit`, with `returnIdsOnly`/`objectIds=...` window fallback when the layer reports `supportsPagination=false`. Supports `--base`, `--output`, `--folder`, `--service`, `--service-type`, `--layer`, `--page-size`, and `--dry-run`; also writes `_catalog_<ts>.json` (discovered services) and `_summary_<ts>.json` (run report + per-layer manifests) at the output root. Datasets that lived only as Opendatasoft uploads (RVVCCA history CSVs, noise sensors, all `presupuesto-*` tables, etc.) are NOT on the geoportal and won't appear in the output.

### Fixed
- **Silent fetch-error masking in `producer/{air,weather}_producer.py`.** The Opendatasoft outage went undetected for ~5 weeks because the previous `fetch_since` swallowed every exception and printed a misleading `[air]/[weather] no new records`. The new implementation logs the exception type, the failing URL, and the page offset on every fetch failure, so future upstream changes surface within minutes.
- CI lint job (`.github/workflows/test.yml`): pinned `ruff` to `0.14.6` (was unpinned `pip install ruff`). Unpinned installs were pulling `ruff 0.15.x`, whose formatter strips redundant outer parentheses in `lambda` bodies and produced `Would reformat: scripts/weather_snapshot_watcher.py` despite local checks passing on the lockfile-pinned 0.14.6.
- `scripts/weather_snapshot_watcher.py`: removed redundant outer parens in the `sorted(rows, key=lambda x: x.get("objectid", 0) or 0)` key so the file is also clean under `ruff 0.15.x` formatter (verified with both 0.14.6 and 0.15.12).

### Deprecated
- `scripts/bulk_download.py` and `scripts/print/print_all_datasets.py`: now require `--allow-legacy` and exit cleanly otherwise. Both target the decommissioned Opendatasoft catalog and have no automatic ArcGIS replacement (the geoportal MapServer is per-domain, not a single global catalog).

### Notes / clarifications
- The pipeline is incrementally rebuildable: existing per-station offsets in `/state/state.json` (last seen ISO timestamps from before the outage) remain valid; the new producers will resume by emitting everything strictly newer.
- The data gap during the outage is irrecoverable: ArcGIS `MedioAmbiente/MapServer/156` and `/157` are live snapshots without historical query, so air readings between `2026-03-31T09:00:00Z` and resumption, and weather readings between station-specific offsets (`2026-02-05T07:20:00Z` for `W05_VALENCIA_UPV_10m`, `2026-03-08T17:50:00Z` for the 10m fleet, `2026-03-31T09:00:00Z` for the rest) and resumption, were never persisted upstream and cannot be backfilled from the API. RVVCCA-style historical data is still available via the CSVs in `backfill/`.
- Empirically validated that `precip_mm` is per-reading rainfall accumulated within the station's reporting interval (≈10 min for `*_10m` stations, hourly for some others), not a cumulative running total: values rise and fall non-monotonically within a day, and per-station daily `sum(precip_mm)` is materially larger than `max(precip_mm)` in rainy periods.
- Continuous aggregates use `WITH (timescaledb.continuous)`; refresh policies are unchanged: `weather.daily` 60d/1d/1h, `weather.weekly` 180d/1d/4h.
