## [Unreleased]
### Removed
- `docs/palettes.json`: a stale copy with 6 palettes that no code read. Design values now live in the `cosmetics` repo. Grafana dashboards keep their literal colours, because dashboard JSON has to embed them.

### Security
- `db/init/020-vlc-password.override.sql` is no longer tracked: `scripts/sync-dev-secrets.sh` generates it, and the
  dev password it carried has been rotated. `.gitignore` keeps the file out.
- `.gitleaksignore`: lists the four history findings of the new `sql-password-literal` rule, two for the rotated password and two for a sample in `docs/rotate_password.txt`.
- `monitoring/alertmanager/alertmanager.generated.yml` is the one plain copy of the Gmail app password, a documented exception to the shared setup, because Alertmanager reads its password only from a file. `scripts/sync-dev-secrets.sh` reads it from the keyring, so `.env` never holds it, and restricts the file to `600` before writing it.

### Changed
- `.env.example`: says where secrets go here, and why the acidbase keyring move does not apply.
- `tests/README.md`: setup now uses `uv sync --extra dev` and tests run through `uv run`, replacing the `uv pip` and `pip` steps. It also warns that plain `uv sync` removes what only the `dev` extra provides, such as `pytest-docker`.
- `.gitignore`, `.gitleaks.toml`: dropped the blanket `*.sql` ignore, which kept new SQL files out of Git without a word, and added the `sql-password-literal` rule, because the upstream rules miss a password written as a SQL literal. The `db/`, `backfill/` and `dbt/` re-includes went with it.
- `.github/workflows/lint.yml`: the gitleaks download retries with `--retry 5`, because a transient 504 from GitHub's release host failed `lint` on code that was fine.
- `.github/workflows/lint.yml`, `.gitleaks.toml`: the gitleaks job checks its download against a pinned SHA-256 and runs `gitleaks git`, because `detect` is deprecated. Docs and changelogs are scanned now; false positives go in `.gitleaksignore`.
- Aligned with the canonical acidbase ruff setup: `pyproject.toml` drops `[tool.isort]` and takes the canonical `[tool.ruff]` tables, keeping `N` (pep8-naming) in the selection. `.github/workflows/lint.yml` and the missing `.gitignore` rules arrive through `acidbase scaffold`, and `.python-version` is committed so CI tests a chosen Python. `.gitleaksignore` records one reviewed false positive in history, a placeholder in a removed README.
- Adopted the canonical non-truncating CLI help from acidbase: the top-level command group is now built with `acidbase.cli_utils.group` (a `click.Group` subclass) instead of `click.group`. Click's default group listing truncates each command's short help at 45 characters, so longer descriptions ended in `...`; the shared group wraps the full first paragraph onto aligned continuation lines instead. `RichGroup.main` also routes output through `ensure_unicode_safe_streams()`, so non-ASCII help (em dashes, accented words) survives on Windows consoles using a legacy code page. `uv.lock` pins acidbase at the commit providing `cli_utils`.

### Added
- `.pre-commit-config.yaml`: a repo-local `uv-export-producer` hook regenerates `producer/requirements.txt` whenever `uv.lock`, `pyproject.toml` or that file is staged. `uv add` and `uv lock` otherwise leave it stale, and a hand export can bring back the lines that broke the producer build. The entry must stay identical to the command stamped in the file's header, which `acidbase` security patching reruns.
- **Validity layer** `dbt/models/staging/stg_weather__clean.sql` (→ `weather.clean`) and `stg_air__clean.sql` (→ `air.clean`): raw hypertables stay immutable (audit trail); the clean views NULL physically impossible measurements **per column** (never dropping rows) and record reasons in a `quality_flags` array (`metric:reason`). Two detectors, parametrized as dbt vars in `dbt/dbt_project.yml` (`weather_validity_bounds`, `air_validity_bounds`, `weather_spike_rules`) with a shared `out_of_bounds` macro (`dbt/macros/validity.sql`): static physical bounds, plus per-metric single-reading spike rules (deviation > max_delta vs. the previous reading within window_minutes, confirmed by V-shape or missing next reading) that catch in-bounds glitches like the −7.8 °C reading at `W02_NAZARET_10m` on 2026-05-15 (19.6 °C ten minutes earlier, the only such jump in ~193k rows). Humidity bound is 1–105 %, not 100: supersaturation and sensor tolerance per `docs/relative_humidity_above_100.txt`.
- Pressure spike rule added to `weather_spike_rules` (max_delta 15 hPa, window 30 min), applied by `stg_weather__clean.sql` through the same Jinja loop as the temperature rule. Calibration: real sea-level pressure never moves 15 hPa within 30 minutes, and only 8 such deltas exist in ~11k close-gap pairs — all within the `W02_NAZARET_10m` barometer failure of 2026-05, where readings oscillated 928↔1016 hPa (the suspicious 949 hPa `min_pressure_hpa` record sat between 928 and 966 neighbours). Verified live: 4 readings of 2026-05-19 (953/928/949/966 hPa) now carry `pressure_hpa:spike` in `public.data_quality`, and `min_pressure_hpa` moved off the 949 excursion — to 950 hPa at 14:20 the same day, i.e. still inside the failure episode. Known limitation (documented at the vars): sustained failure stretches whose consecutive readings agree with each other evade single-point rules by design — an episode-level detector (e.g. rolling variance) is the next escalation if fully credible pressure minima are required; until then the quality mart keeps the episode visible.
- `dbt/models/marts/data_quality.sql` (→ `public.data_quality`): sensor-health observability — flagged-value counts per schema/station/month/flag; exposed as `vlc quality` (`src/vlc/cli.py`, `queries.QUALITY`). Live findings: all weather flags concentrate on `W02_NAZARET_10m` (58 impossible pressure readings in 2026-05 ≈ 8 % of the month, 1 temperature spike, 2 pressure glitches 2022-09, 4 humidity > 105 in 2020-01); no air violations.
- `dbt/models/marts/weather_records.sql` (→ `public.weather_records`): "records of records" mart — the full `weather.hyper` row holding each meteorological extreme (max/min of `temperature_c`, `humidity_pct`, `pressure_hpa`, `wind_speed_ms`; max of `precip_mm`), ties resolved by earliest `ts`, generated via a Jinja loop over the extreme definitions. Promoted from the ad-hoc block in `db/direct_sql_queries.txt` (now a one-line pointer to the mart). Documented in `dbt/models/marts/_marts.yml` with `not_null`/`unique`/`accepted_values` tests on `record_type` (all passing via `dbt build --select weather_records`). Exposed as `vlc records` (`src/vlc/cli.py`, `src/vlc/queries.py` `RECORDS`); listed in `README.md`. Live output verified identical to the original ad-hoc query. Note: the live rebuild used a `models/` bind-mount because Docker Hub was unreachable for an image rebuild (`python:3.12-slim` manifest fetch timed out); the baked image will pick the model up on the next `--build`.
- CLI data commands reading exclusively from the dbt-managed views (single source of truth shared with Grafana): `vlc status` (`public.data_freshness`), `vlc latest [--weather|--air|--all]` (`weather.latest` / `air.latest` / `public.station_snapshot`), `vlc stations` (`public.stations`). New modules `src/vlc/queries.py` (presentation-only SELECTs), `src/vlc/db.py` (transport: `docker compose exec -T timescaledb psql --csv` by default — keeping the no-published-ports posture — with a `VLC_DSN` psycopg2 fallback), rich-table/`--csv` rendering in `src/vlc/cli.py`.
- SSOT guardrail `vlc grafana check` (`src/vlc/grafana_check.py`): walks every `rawSql` in `grafana/dashboards/*.json` and `grafana/provisioning/alerting/*.yml` and fails when derived-logic markers (`DISTINCT ON`, `max(ts)`, `now() - ts`) target the raw hypertables instead of the dbt views. Wired as a CI step in `.github/workflows/test.yml`. Immediately proved its worth by catching two duplicated-logic panels (`system_metrics.json` "Station Inventory" and "Data Freshness") that manual review had missed — the latter still carried the outdated 6 h threshold.
- `dbt/models/staging/stg_weather__latest.sql`, `stg_air__latest.sql`: expose `age_s` (`extract(epoch from now() - ts)`) and the PostGIS `geo` column so dashboards/CLI never re-derive data age and the spatial panel can filter on the view.

### Added
- `grafana/provisioning/alerting/vlc-staleness.yml`: Grafana-managed alert rule `WeatherStationStale` (folder `VLC`, evaluated every 5 m, `for: 5m`, severity `warning`): queries TimescaleDB for `EXTRACT(EPOCH FROM (now() - max(ts))) / 3600.0` per `fiwareid` in `weather.hyper` and fires one alert instance per station exceeding 5 hours of staleness. Complements the topic-level Prometheus `NoWeatherDataIngested` alert, which cannot detect a single dead station while the rest of the fleet keeps publishing. Verified live: `W05_VALENCIA_UPV_10m` (≈3555 h stale) enters `Pending`→`Firing`, all other stations stay `Normal`.
- `producer/arcgis_client.py`: shared ArcGIS REST client (`get_layer_metadata`, `get_field_names`, `fetch_one_feature`, `fetch_page`).
- Stale-upstream heartbeat in both producers: after `VLC_STALE_WARN_EVERY` consecutive empty cycles (default 12 ≈ 1 hour at the 5-minute cadence) the log line includes how long it has been since the last successful emit.
- `db/init/010-bootstrap.sql`: `weather.daily` and `weather.weekly` continuous aggregates now expose `sum(precip_mm) AS precip_total_mm` alongside the existing `max(precip_mm) AS precip_max_mm`. The `max` is the peak per-interval rainfall intensity in the bucket; `sum` is the bucket's total rainfall (since each `precip_mm` row is the rainfall accumulated within that station's reporting interval).
- `grafana/dashboards/weather.json`: new "Daily Precipitation Total - All Stations (Last 30 days)" panel sourcing `weather.daily.precip_total_mm` (full-width bar chart, `lengthmm` unit, legend `sum` reducer). The existing 7-day per-reading precipitation panel is kept for intensity views.
- `db/direct_sql_queries.txt`: "Records of records" block that surfaces the row holding each meteorological extreme (`max/min` of `temperature_c`, `humidity_pct`, `pressure_hpa`, `wind_speed_ms`; `max` of `precip_mm`) via per-metric `UNION ALL` subqueries.
- `db/direct_sql_queries.txt`: all weather hourly-aggregate variants (since-always, since-Monday, since-today, hour-of-day across all years) now also select `SUM(precip_mm) AS precip_total_mm` next to `MAX(precip_mm) AS precip_max_mm`.
- `scripts/arcgis_bulk_download.py`: ArcGIS-side bulk catalog dumper, the replacement for the legacy Opendatasoft `scripts/bulk_download.py`. Pure stdlib (`urllib.request`), no new dependencies. Recursively walks `<base>/services?f=json` to discover every folder/service, enumerates `layers[]` + `tables[]` on each MapServer/FeatureServer, and writes a per-layer folder named `<folder>__<service>__<layer_id>__<slug>/` with `<slug>_full_<ts>.json` (features array; Point geometry flattened to `lon`/`lat`, other geometry kept under `_geometry`) and `<slug>_metadata_<ts>.json` (download manifest + ArcGIS layer JSON). Pagination honors the layer's `maxRecordCount` and `exceededTransferLimit`, with `returnIdsOnly`/`objectIds=...` window fallback when the layer reports `supportsPagination=false`. Supports `--base`, `--output`, `--folder`, `--service`, `--service-type`, `--layer`, `--page-size`, and `--dry-run`; also writes `_catalog_<ts>.json` (discovered services) and `_summary_<ts>.json` (run report + per-layer manifests) at the output root. Datasets that lived only as Opendatasoft uploads (RVVCCA history CSVs, noise sensors, all `presupuesto-*` tables, etc.) are NOT on the geoportal and won't appear in the output.

### Fixed
- **Links in alert emails open.** They named the container's hostname, which nothing outside Docker can resolve. `--web.external-url` in `compose/docker-compose.yml` now gives `http://localhost:8080/alertmanager/` and `/prometheus/`, and `compose/nginx.conf` routes both behind the existing basic auth. `--web.route-prefix=/` keeps them serving from the root for Prometheus and Grafana. `monitoring/README.md` drops the direct ports `9090` and `9093`, which were never published.
- **Alertmanager can send email.** Four faults were stacked: the generated config had no SMTP values, because `.env.example` ships them blank; `nobody` in the image could not read a `600` file; `smtp_require_tls: true` demands STARTTLS, which Gmail's port 465 does not offer; and `vlc_internal` has no route out. `monitoring/alertmanager/alertmanager.yml`, `scripts/sync-dev-secrets.sh` and `compose/docker-compose.yml` now use the shared Gmail sender on port 465, run the container as UID 1000 with its state in the gitignored `monitoring/alertmanager/data/`, and add `vlc_frontend`. `SMTP_TO` in `.env` replaces the other `SMTP_*` settings.
- **Password rotation drill.** `docs/rotate_password.txt` step 3 had a literal sample password in its `ALTER ROLE` line, and step 5's `SELECT 1` runs over the local socket, which checks no password, so a pasted sample looked like success while every real login failed. Step 3 now applies the generated `db/init/020-vlc-password.override.sql` with `psql -f`, so nothing is typed, step 5 makes a real login and lists the connector states, and the sample uses a `REAL` placeholder.
- **Producer images build again.** Since 2026-08-05, `producer/requirements.txt` carried `-e .` and `acidbase @ git+https://...`, and the slim image has neither a project in `/app` at that point nor `git`, so every `--build` failed; the running images dated from May. The file now comes from `uv export --frozen --no-hashes --no-dev --no-emit-project --no-emit-package acidbase -o producer/requirements.txt`, with the same 42 pins, and rebuilt producers take the pins raised since May. `docs/rotate_password.txt` also keeps `PGPASSWORD` a reference to `VLC_DEV_PASSWORD`, because the producers read it.
- **`dbt/models/` is now tracked.** `.gitignore` hid all 16 model files through `models/` and `*.sql`, so a fresh clone had the docs, marts references and tests but no models to build, and the only copy lived on the working machine. `.gitignore` re-includes `dbt/models/` and any `dbt/**/*.sql`, so new macros and tests are not hidden either; `dbt/target/`, `dbt/dbt_packages/` and `dbt/logs/` stay ignored.
- **Silent fetch-error masking in `producer/{air,weather}_producer.py`.** The Opendatasoft outage went undetected for ~5 weeks because the previous `fetch_since` swallowed every exception and printed a misleading `[air]/[weather] no new records`. The new implementation logs the exception type, the failing URL, and the page offset on every fetch failure, so future upstream changes surface within minutes.
- CI lint job (`.github/workflows/test.yml`): pinned `ruff` to `0.14.6` (was unpinned `pip install ruff`). Unpinned installs were pulling `ruff 0.15.x`, whose formatter strips redundant outer parentheses in `lambda` bodies and produced `Would reformat: scripts/weather_snapshot_watcher.py` despite local checks passing on the lockfile-pinned 0.14.6.
- `scripts/weather_snapshot_watcher.py`: removed redundant outer parens in the `sorted(rows, key=lambda x: x.get("objectid", 0) or 0)` key so the file is also clean under `ruff 0.15.x` formatter (verified with both 0.14.6 and 0.15.12).

### Notes / clarifications
- Docker Desktop (WSL2 backend) served **stale build-context content** for files edited via the Windows `\\wsl$` path: `docker compose build dbt` — even with `--no-cache` — kept baking a pre-pressure-rule `stg_weather__clean.sql` (in-image md5 differed from the WSL-side file), while bind mounts read fresh content. The live apply therefore ran `dbt build` with `dbt/models` + `dbt_project.yml` bind-mounted (`--no-partial-parse`). The `vlc/dbt` image stays stale until Docker Desktop's file-share cache is flushed (restart Docker Desktop or `wsl --shutdown`) and `docker compose ... build dbt` is re-run; the database views themselves are correct and current.
- The pipeline is incrementally rebuildable: existing per-station offsets in `/state/state.json` (last seen ISO timestamps from before the outage) remain valid; the new producers will resume by emitting everything strictly newer.
- The data gap during the outage is irrecoverable: ArcGIS `MedioAmbiente/MapServer/156` and `/157` are live snapshots without historical query, so air readings between `2026-03-31T09:00:00Z` and resumption, and weather readings between station-specific offsets (`2026-02-05T07:20:00Z` for `W05_VALENCIA_UPV_10m`, `2026-03-08T17:50:00Z` for the 10m fleet, `2026-03-31T09:00:00Z` for the rest) and resumption, were never persisted upstream and cannot be backfilled from the API. RVVCCA-style historical data is still available via the CSVs in `backfill/`.
- Empirically validated that `precip_mm` is per-reading rainfall accumulated within the station's reporting interval (≈10 min for `*_10m` stations, hourly for some others), not a cumulative running total: values rise and fall non-monotonically within a day, and per-station daily `sum(precip_mm)` is materially larger than `max(precip_mm)` in rainy periods.
- Continuous aggregates use `WITH (timescaledb.continuous)`; refresh policies are unchanged: `weather.daily` 60d/1d/1h, `weather.weekly` 180d/1d/4h.
